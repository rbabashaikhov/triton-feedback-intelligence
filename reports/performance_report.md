# Отчёт: оркестрация моделей в NVIDIA Triton

## 1. Цель

Развернуть три разнородные ML-модели в NVIDIA Triton,
связать их через Business Logic Scripting и провести
нагрузочное тестирование отдельных моделей и всей цепочки.

Эксперимент выполняется на CPU.

## 2. Окружение

| Параметр | Значение |
|---|---|
| Облачный провайдер | Yandex Cloud |
| ОС | Ubuntu 24.04 |
| CPU | 16 vCPU |
| RAM | 64 GiB |
| GPU | Нет |
| Triton | 2.74.0, CPU-only |
| ONNX Runtime | Backend |
| Python Backend | BLS, embedding, generation |

## 3. Архитектура

Пайплайн состоит из четырёх Triton-моделей:

1. embedding_model — multilingual-e5-small;
2. classifier — Logistic Regression в ONNX;
3. llm_generator — Qwen2.5-0.5B-Instruct GGUF Q4_K_M;
4. feedback_pipeline — Python BLS.

Для жалоб и вопросов вызывается генерация.
Для положительных отзывов генерация пропускается.

## 4. Подготовка классификатора

Учебный датасет:
- 30 примеров;
- 3 класса;
- 21 пример для обучения;
- 9 примеров для тестирования.

Результаты теста:
- Accuracy: 1.00;
- Macro F1: 1.00;
- размер ONNX: около 6,2 КБ;
- размер входа: 384;
- размер выхода: 3.

Ограничение: тестовая выборка слишком мала для достоверной
оценки качества на реальных данных.

## 5. Локальный интеграционный тест

### Положительный отзыв

Текст: "Отличный магазин, спасибо!"

Категория: positive
Уверенность: 0.4334
LLM: не вызывается.

### Вопрос

Текст: "Когда доставят мой заказ?"

Категория: question
Уверенность: 0.4371

Ответ LLM:
"Мы всегда готовы доставить заказы в течение следующих
дней: 1-2 недели."

Проблема: модель выдумала срок доставки.

### Жалоба

Текст: "Товар пришёл повреждённым."

Категория: complaint
Уверенность: 0.4043

Ответ LLM:
"Я не могу помочь с этим."

Проблема: низкое качество ответа.

### Вывод

Локально проверена последовательность:
эмбеддинг -> классификация -> условная генерация.

Все три тестовых обращения получили ожидаемые классы.
Но уверенность низкая, а ответы генератора требуют улучшения.

Тест не проверяет выполнение BLS внутри Triton.

## 6. Проблемы развёртывания

### NVIDIA Container Registry

Реестр nvcr.io возвращал HTTP 403 Forbidden.
Готовый контейнер Triton загрузить не удалось.

Выбран вариант сборки CPU-only из официальных исходников.

### Сборка ONNX Runtime

При первой попытке ONNX Runtime пытался использовать
CUDA-образ из недоступного NVIDIA Registry.

Исправлена конфигурация:

TRITON_BUILD_CONTAINER=ubuntu:24.04
TRITON_ENABLE_GPU=OFF
TRITON_ENABLE_ONNXRUNTIME_OPENVINO=OFF

### Зависшая загрузка Git

Клонирование triton-inference-server/common.git
зависло внутри сборочного контейнера.

Тестовое клонирование через HTTP/1.1 прошло успешно.
После настройки Git и прерывания зависшей сетевой
операции CMake продолжил сборку.

## 7. Серверная интеграция

Статус: завершена. Все четыре модели загружены в Triton со статусом READY, BLS-инференс проверен на трёх обращениях.

Необходимо зафиксировать:

- успешный вызов BLS через HTTP;
- ответ тестового клиента.

## 8. Методика нагрузочного тестирования

Инструмент: NVIDIA Perf Analyzer.

Планируемые уровни конкурентности: 1, 2, 4, 8.

Тестируются:
- classifier;
- embedding_model;
- llm_generator;
- feedback_pipeline с генерацией;
- feedback_pipeline без генерации.

Необходимо указать:
- версии Triton и Perf Analyzer;
- размер батча;
- длительность и прогрев тестов;
- длину входного текста;
- лимит выходных токенов генерации;
- модель нагрузки;
- загрузку CPU и использование RAM.

Все измерения проводились на Yandex Cloud VM с 16 vCPU,
на NVIDIA Triton 2.74.0 в CPU-only режиме.

Протокол: HTTP. Batch size: 1.

|---|---:|---:|---:|---:|
| ONNX classifier | 1 | 4876.33 | 0.198 | 0.242 |
| ONNX classifier | 2 | 10008.20 | 0.192 | 0.236 |
| ONNX classifier | 3 | 12893.20 | 0.225 | 0.281 |
| ONNX classifier | 4 | 13546.60 | 0.287 | 0.347 |
| E5 embedding | 1 | 64.88 | 15.375 | — |
| E5 embedding | 2 | 66.46 | 30.038 | 31.796 |
| BLS without generation | 1 | 59.71 | 16.727 | — |
| BLS without generation | 2 | 61.74 | 32.349 | 33.449 |
| Qwen GGUF | 1 | 0.909 | 1073.738 | 1783.538 |
| BLS with generation | 1 | 0.869 | 1103.507 | 1809.485 |

Прочерки обозначают метрики, пока не извлечённые
из исходных CSV или логов.

Для генеративных сценариев использовались 20 измеряемых
запросов после двух прогревочных. Для остальных —
стандартные временные окна Perf Analyzer.

### Интерпретация

1. ONNX-классификатор очень быстрый и не является
   основным ограничением производительности.
2. E5 определяет скорость пайплайна без генерации.
3. Qwen становится главным ограничением при генерации.
4. Условная маршрутизация BLS позволяет избежать
   дорогостоящего вызова LLM для положительных отзывов.
5. Рост конкурентности с 1 до 2 практически не увеличил
   throughput для E5, но существенно увеличил latency.

Сравнение веток BLS показывает около 59.71 RPS без
генерации и 0.869 RPS с генерацией — разница примерно
в 69 раз.

Важно: нагрузочные данные и длина выходных текстов
могут различаться, поэтому это сравнение сценариев,
а не строго изолированный эксперимент.

Исходные результаты сохранены в benchmarks/.

## 11. Triton против FastAPI

Triton предоставляет:
- унифицированное обслуживание разных ML-бэкендов;
- управление экземплярами и версиями моделей;
- встроенные метрики инференса;
- dynamic batching для совместимых моделей;
- внутреннюю оркестрацию через BLS.

FastAPI предоставляет более универсальный инструмент
для разработки HTTP API и прикладной бизнес-логики.

Преимущества Triton по производительности необходимо
оценивать экспериментально. Само наличие Triton
не гарантирует меньшую latency или больший RPS.
